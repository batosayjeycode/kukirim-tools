# kukirim-tools

Source for **https://tools.kukirim.com** — free browser-based tools for Indonesian online sellers (profit calculator, parcel-label generator, spreadsheet templates).

The main SEO site `kukirim.com` lives in a separate repository, `kukirim-site`.

See [`PLAN.md`](./PLAN.md) for scope, approved decisions (§0), and the step-by-step roadmap with current status (§0.9).

## Requirements

- Node.js ≥ 22.23.4 (required by Astro 7). With nvm: `nvm install && nvm use` (reads `.nvmrc`).

## Commands

| Command | Action |
|---|---|
| `npm install` | Install dependencies |
| `npm run dev` | Dev server at `http://localhost:4321` |
| `npm run build` | Production build to `dist/` |
| `npm run preview` | Preview the production build |
| `npm test` | Run unit tests and DOM smoke tests (Vitest; DOM tests need a build) |
| `npm run verify` | Build, then run all tests and the SEO check (same as CI) |
| `npm run check:seo` | After a build: checks titles, descriptions, canonical, Open Graph, sitemap, JSON-LD, and internal links in `dist/` |
| `npm run check:launch` | Fails while required contact details are unset or pages are not ready |

## Structure

```text
public/              static files (robots.txt, favicon, downloads)
src/config.js        site info, contact details (null until set), page registry
src/layouts/         BaseLayout (SEO meta, canonical, OG)
src/components/      Header, Footer, Field
src/lib/             pure, unit-tested logic (profit, format, csv, labels)
src/scripts/         browser glue per tool page (DOM only, textContent output)
src/pages/           routes (trailing slash, directory output)
src/styles/          global.css
tests/               Vitest unit tests
scripts/             build-templates.py: regenerates the .xlsx templates in public/downloads/
```

## Testing

- `tests/*.test.js`: unit tests for the pure logic in `src/lib/` (profit, formatting, CSV, labels, downloads, config).
- `tests/dom/*.test.js`: smoke tests that load the built page from `dist/` into happy-dom and run the real page script (calculator flows, label manual entry, CSV import, sender opt-in storage, print layout). They are skipped when `dist/` is missing, so run `npm run verify`.
- `npm run check:seo`: checks the built HTML (metadata, canonical, sitemap, JSON-LD, internal links).
- CI (`.github/workflows/ci.yml`) runs `npm ci && npm run verify` on pushes to `main` and on pull requests; on `main` it then deploys the verified `dist/` to Cloudflare Pages.
- Manual QA (2026-10-26): Lighthouse 13.5 (mobile) scored 100 for performance, accessibility, best practices, and SEO on all 9 indexable pages; keyboard navigation and console checked in Chrome. Print output on a real thermal printer is not yet tested.

## Configuration before launch

Edit `src/config.js`:

- `CONTACT` — real business name, email, and optional WhatsApp/Instagram. Unset (`null`) fields are hidden on the site; placeholder text is never rendered. `missingLaunchValues()` lists required values still unset.
- `PAGES[].ready` — set to `true` when a page exists, so it appears in navigation.

## Spreadsheet templates

The free `.xlsx` templates in `public/downloads/` are generated by `python3 scripts/build-templates.py` (requires `openpyxl`). The files are committed, so this is only needed when changing a template. Sample data is fictitious.

## SEO assets

- Social preview image `public/images/og-default.png` (1200 × 630) is rendered from `scripts/og-image.html` with headless Chrome; the command is in that file.
- `public/_headers` sends `X-Robots-Tag: noindex` on `*.pages.dev` hosts so only `tools.kukirim.com` is indexed.

## Before launch

- `npm run check:launch` must pass: real contact details in `CONTACT`, and `LEGAL_REVIEW` set to `true` after the owner reviews the privacy and terms drafts.
- The privacy page states only that the site's own code sets no cookies. Review `/privasi/` whenever Cloudflare security, bot protection, analytics, or other features that may set cookies or process visitor data are enabled, and update it if actual behavior changes.
- `public/_headers` sets a strict Content-Security-Policy (same-origin scripts only, no network requests) plus `nosniff`, `X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy` and HSTS. Cloudflare features that inject scripts (Web Analytics, Rocket Loader, email obfuscation, bot challenges) are blocked by it: update the CSP when enabling one, and check the pages still work. `tests/headers.test.js` checks the policy and that built pages have no inline scripts or external assets.
- `SITE.mainSiteLive` stays `false` until `kukirim.com` is deployed (PLAN.md §0.9, task P1).

## Privacy

All tools run in the browser. Recipient/CSV data is never sent to a server or stored. Sender details are stored in `localStorage` only after explicit opt-in.

## Deployment (Cloudflare Pages)

Deployed by GitHub Actions, not by Cloudflare's Git integration: the `check` job builds and verifies, uploads `dist/`, and the `deploy` job (pushes to `main` only) first runs `npm run check:launch` — so nothing is published while contact details or the legal review are missing — then runs `wrangler pages deploy dist --project-name=kukirim-tools --branch=main`. It needs a Direct Upload Pages project named `kukirim-tools` and the repository secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`. Custom domain `tools.kukirim.com`. Not deployed yet — see PLAN.md §0.9 Step 10.
